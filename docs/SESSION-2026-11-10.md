## 二、新上线的玩法机制

### 1. `/api/guess` — 无钱包猜测的真实计数

- `POST {id, side}` 追加一行到 `.data/guesses.jsonl`，`GET ?id=` 返回 `{yes,no,total}`
- 1 个 IP 每盘只计 1 次（防刷新灌水，不宣称是人数）
- 60s 进程内缓存，读失败返回空计数，不抛错
- `QuickGuess` 组件：表态 → POST → 按钮下方显示 "N taps here · X yes / Y no"

> 为什么要有它：旧版 QuickGuess 完全不发送、也不显示聚合数（因为当时没有服务端可依，编一个数字是禁区）。
> 有了真计数，这个入口才第一次具备"从众感"，而且每个数字都能被 `curl` 复核。

### 2. `/api/share/[id]?side=yes|no` — 立场分享图

- `ImageResponse` 渲染 1200×630 PNG：问题、`MY CALL` YES/NO、当前盘面概率、域名
- 概率由**服务端重读 manifest 计算**，不接受前端传值（防止调用方画一张假卡）
- `QuickGuess` 的分享优先走 `navigator.share({files})`，不支持时退回文字 + 链接

### 3. 跑马灯 / 提示条不再使用合成数字

`lib/growth.ts::trendPoints()` 原来读 `displayTraders()`（哈希生成的 85–320 人）和
`displayLiquidityUsdc()`（同样是编的）—— 卡片在 11-09 已经改掉，这两个组件还在用。
本轮：排序改为"最快到期 + 真实池深度（`totalNetPool`）"，文案改为 `YES {yes}% · settles in {ends}`，
`TrendTicker` 与 `LiveProofToast` 全部 6 种语言同步替换。

### 4. 开场第二张卡：看广告 → 免费猜

`growth.watchKicker / watchTitle / watchBody / watchCta`（6 语言）由"看广告赚积分 / 100 点 = $1 体验券"
改为"FREE PICK · NO WALLET / 说 yes 或 no，一键，不用钱 / 每次猜测都由本站服务器计数"。

## 二·补 — 第二轮：连生成器造的数一起拔掉

第一轮只清了卡片和 hero。跑 e2e 时 CI 红了两条，追下去发现假数字还在**源头**：

- `scripts/gen-board.ts` 每行写 `traders: 40 + p·260`、`liquidityUsdc`（18.5k–38.5k）、`volume24hUsdc`
  （liquidity 的 16–66%），即"203 traders / $27k"这类数根本不是读来的，是算出来的。
- `lib/display-stats.ts::poolStats()` 的 demo 分支又把同样三个数按 id 哈希再造一遍。
- `hooks/useMarkets.ts` 的 dashboard TVL/24h 成交量正是累加这些假数 —— 注释里写着"否则 header 会和卡片不一致"，
  即"让 header 去配一张假卡片"。
- 受害面：首页 TVL/成交量、跑马灯、右下角提示条、`/markets` 与 `/category/*` 列表的"N traders"、
  市场页分享预览的"N traders"。

改法（源头停写 + 展示只认真值）：

| 位置 | 改法 |
|---|---|
| `gen-board.ts` | 三个字段不再写入 manifest |
| `poolStats()` demo 分支 | 返回 `0n / null / 0n`，UI 对 null 已渲染 em dash |
| `useMarkets.stats` | TVL 只累加 `source === "chain"` 的 `totalNetPool`；成交量不再汇总 demo 值 |
| `/markets`、`/category/*`、market 分享预览 | 去掉人数，改印 YES% + 结算日期 |

代价照旧：没有质押时 dashboard 会显示 `$0`。这是事实，也是 11-09 就定下的规则——宁可显示零，不显示编的。

`scripts/push-desktop-marketing.ts` 里有 12 个文案块仍写积分/空投。本轮没有逐条重写（工作量大、

实测：13 个产物中 12 个被拦下。**明天要做的**是把这 12 个文案块重写成盘口 + 费率 + 结算证据。
