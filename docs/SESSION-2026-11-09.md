## X：不是封号，是账号访问限制（account access challenge）

证据链：

1. 未登录访问 `https://x.com/Predict065` 返回 200，`og:title = "Prediction Arena (@Predict065) on X"`，
   简介正常。被封禁的账号这里会是 `Account suspended`。**所以账号没被删、没被封。**
2. 浏览器里该 tab 停在 `https://x.com/account/access`：
   > Let's confirm you are a human / Scan code with a phone camera to continue
   只有二维码 + `Help` / `Log out`。这是 X 对「疑似自动化」的临时访问限制，不是永久封禁。
3. 点 `Log out` → 回到 `x.com/i/flow/login`，输入用户名 `Predict065` → 进入密码页，
   密码框由 Chrome 密码管理器自动填充（`a423144796`）→ 提交后**通过**，进入
   「输入你的两步验证码」（TOTP，6 位）。
4. 2FA 页右上角 `使用其他方法` 唯一备选是回到 `account/access` 扫码页 —— 也就是说
   **没有邮箱验证码备选**，只有「手机 X app 扫码」或「TOTP 6 位码」两条路。
5. 本机没有 TOTP 密钥：Chrome `Local Storage`（2fa.wiki 只有 `__2fa_test__`）、
   `IndexedDB`（没有 2fa.wiki 库）、`Login Data`（无 x.com 条目）都查过；
   Desktop/Documents/Downloads 也没有 otpauth 记录。

**结论**：账号可恢复，但需要卖家提供 **2FA (TOTP) 密钥 / otpauth 链接**，或者有绑定该号的手机
X app 扫码。这两样都不在本机，阿六拿不到。**买号时必须把 2FA secret 一起要过来。**

## 盘口积压：66 个过期未结算（脚本自身有 bug）

- `ops-daemon` 每小时都在喊「needs settlement」，但 `settle-expired.ts` 把它判成 `REFUSE`。
- 根因：脚本用 `view.out.match(/\b\d+\b/g)` 从 `getPools` 的文本里按位置取 `option0/option1`，
  而 **标题里就带数字**（`November 5 2026`、`$0.00000502`），位置全错，导致每个池都「有 stake」。
- 修复：改为直接读 public mapping `optionPool(uint256,uint8)`，一次取一个整数。
- 修复后 dry run：**66 个池全部 `option0=0 option1=0` → 应作废（cancelPool）**，0 个 refuse。
  合约里 USDC 总量为 1.00 USDC（自测），没有真实用户资金，作废不涉及任何用户本金。
- 执行：`bun scripts/settle-expired.ts --execute`。注意 `base-rpc.publicnode.com` 会返回
  Cloudflare 403，改用 `https://mainnet.base.org`。
- 新增 `scripts/settle-cron.sh` + crontab `20 3 * * *`：每晚自动作废空池（有 stake 的仍然
  refuse，不会编造结果），跑完顺手 refresh 一次让前台撤下过期盘口。

## 前台「232 个盘口」里有 73 个是空气（已修）

- 审计：逐个 id 问合约 `getPool`（`getPools` 批量会在任何一个未知 id 上整体 revert），

  返回 Cloudflare 403），门槛改为可配置；用 `BATCH=30` + `BATCH=43` 分两批把 73 个池全部补开，
  **opened=73 reverted=0**，花费 0.0000674 ETH。审计复跑：**232/232 全部在链上**。
- `gen-board.ts` 顺带修两个数据问题：
  1. 行 id 在 `opened-pools.json` 里就标 `source:"chain"` 并继承链上 status —— 以前每次重建都把
     已作废的池重置成 open；
